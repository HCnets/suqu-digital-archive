# 苏区镇数字档案 CMS 落地实施文档

## 1. 文档目的

本文档用于指导“苏区镇数字档案”从当前展示型前端，逐步落地为正式生产可用的后台内容管理系统。

本项目最终形态：

- 展示端：`https://szht.online`
- 管理端：`https://admin.szht.online`
- 后端 API：Node.js + Express
- 数据库：MySQL
- 部署环境：Linux + 宝塔 + Nginx + MySQL
- 内容机制：全量数据库管理、权限控制、审核发布、版本留痕、来源依据、敏感等级、操作审计

本文档只定义落地步骤，不直接开始开发。

## 2. 总体落地原则

### 2.1 先底座，后内容

先完成账号、权限、登录、审计、审核流等底层能力，再迁移具体业务模块。

原因：

- 后台权限和审核机制是所有内容模块的共同基础。
- 如果先做单个模块，后续会反复返工接权限、版本、审核、日志。

### 2.2 先核心闭环，后全量迁移

第一期先完成：

- 后台登录
- 用户权限
- 审核流
- 档案点位
- 留言审核
- 致敬计数
- 媒体库

这些功能完成后，系统已经具备真实后台管理能力。

### 2.3 前台只读已发布数据

前台展示端只消费“已发布”内容。

不允许前台直接读取：

- 草稿
- 待审核
- 已驳回
- 已下架
- 已删除
- 内部审核意见
- 敏感来源附件
- 操作日志

### 2.4 数据真实性优先

所有政治敏感、史料相关内容必须记录来源依据与审核过程。

每条内容至少支持：

- 来源类型
- 来源标题
- 来源链接
- 档案编号或出版物信息
- 页码
- 采集人
- 采集时间
- 可信等级
- 敏感等级
- 风险类型
- 审核记录

### 2.5 不保存明文密码

超级管理员和其他账号密码不得明文保存、明文查询。

允许：

- 首次网页初始化创建超级管理员。
- 服务器命令重置密码。
- 服务器命令生成一次性登录链接。

不允许：

- 后台查看管理员密码。
- 数据库保存明文密码。
- 通过接口返回密码。

## 4. 阶段 0：开发准备与架构确认

### 4.1 阶段目标

在正式开发前确认基础方案，避免后续大规模返工。

### 4.2 主要任务

- 确认本地 MySQL 开发方式：
  - 方案 A：本地安装 Docker，启动 MySQL。
  - 方案 B：本机直接安装 MySQL。
  - 方案 C：使用服务器 MySQL 创建测试库。
- 确认 `.env` 配置规范。
- 确认数据库迁移方案。
- 确认 `admin.szht.online` 的部署方式。
- 确认 API 反向代理方式。
- 确认管理端目录结构：新增 `admin/`。
- 确认后台视觉风格：实用型 CMS。
- 确认阶段 1-3 为第一期里程碑。

### 4.3 交付物

- `.env.example` 配置模板。
- 数据库连接说明。
- 本地开发启动说明。
- 正式服务器部署拓扑。
- 后台菜单结构初稿。
- 权限点清单。

### 4.4 验收标准

- 能确定使用 MySQL 开发和测试。
- 能明确本地、测试、生产三套配置。
- 能明确展示端、管理端、API 的访问路径。
- 阶段 1 开发前没有重大技术路线争议。

### 4.5 风险与注意事项

- 本机没有 MySQL/Docker 时，开发联调会受影响。
- 直接连服务器数据库开发有误操作风险，必须使用测试库。
- 正式生产库不得用于开发调试。

## 6. 阶段 2：统一内容模型与审核流

### 6.1 阶段目标

建立所有内容模块共用的内容、版本、来源、审核、发布机制。

### 6.2 主要任务

#### 数据模型

- 内容主表 `contents`
- 内容版本表 `content_versions`
- 来源依据表 `content_sources`
- 审核流程表 `review_workflows`
- 审核节点表 `review_workflow_steps`
- 审核任务表 `content_review_tasks`
- 内容回收站字段

#### 内容状态

- 草稿
- 待审核
- 初审中
- 终审中
- 已发布
- 已驳回
- 已下架
- 已删除

#### 审核流能力

- 按模块配置审核流程。
- 编辑提交审核。
- 审核员初审。
- 超级管理员终审。
- 驳回到对应节点。
- 驳回原因可选。
- 发布后编辑生成新版本。
- 新版本审核通过后替换公开版本。

#### 后台页面

- 内容统一列表。
- 内容详情页。
- 版本历史页。
- 来源依据编辑页。
- 审核任务列表。
- 审核流程配置页。
- 回收站基础页。

### 6.3 默认审核规则

- 档案/史料：编辑提交 -> 审核员初审 -> 超管终审 -> 发布。
- 群众留言：审核员一审 -> 发布。
- 红歌/影视/路线/题库/英雄谱：审核员初审 -> 超管终审 -> 发布。

### 6.4 验收标准

- 内容可创建草稿。
- 内容可提交审核。
- 审核员可通过或驳回。
- 超级管理员可终审发布。
- 已发布内容修改后不会直接影响前台。
- 前台 API 只返回已发布版本。
- 每次审核动作都有日志。

### 6.5 风险与注意事项

- 内容版本和发布版本必须分离。
- 前台不得读取未发布版本。
- 审核流要可配置，不要写死在单个模块里。

## 7. 阶段 3：核心内容闭环

### 7.1 阶段目标

优先完成最核心、最影响当前前台体验的模块后端化。

范围：

- 档案点位
- 群众留言
- 致敬计数
- 媒体库

### 7.2 档案点位

#### 任务

- 建立档案扩展表。
- 支持标题、摘要、正文、年份、类型、经纬度、媒体、来源依据。
- 支持地图点位展示字段。
- 支持后台增删查改。
- 支持审核发布。
- 支持版本历史。
- 迁移现有 `archives.json` 数据。
- 展示端从数据库读取已发布档案。

#### 验收

- 后台可新增档案。
- 后台可编辑坐标、年份、分类、内容、媒体。
- 未发布档案不出现在前台。
- 审核通过后前台地图和详情可展示。

### 7.3 群众留言

#### 任务

- 建立留言扩展表。
- 前台提交留言进入待审核。
- 后台审核员审核留言。
- 支持屏蔽、删除、恢复。
- 支持 IP 记录。
- 支持敏感等级标记。

#### 验收

- 用户提交留言后不会立刻公开。
- 审核通过后前台显示。
- 驳回或删除后前台不显示。

### 7.4 致敬计数

#### 任务

- 计数值入库。
- 后台可查看当前计数。
- 后台可调整展示值。
- 前台点击写入计数日志。
- 支持限流防刷。

#### 验收

- 前台点击致敬后计数增加。
- 后台可查看和调整。
- 调整行为写审计日志。

### 7.5 媒体库

#### 任务

- 建立媒体表。
- 支持图片上传。
- 支持视频上传。
- 支持分类目录。
- 支持缩略图。
- 支持图片压缩。
- 支持自定义水印。
- 支持文件关联内容。
- 预留 ffmpeg 视频压缩和封面截帧。

#### 验收

- 后台可上传图片。
- 上传后可在档案中选择使用。
- 图片生成缩略图。
- 水印配置生效。
- 文件删除和替换有日志。

### 11.2 部署任务

- 配置 Nginx 反向代理。
- 配置 HTTPS。
- 配置 Node.js 运行方式：
  - PM2，或
  - Docker
- 配置 MySQL 用户权限。
- 配置上传目录权限。
- 配置生产 `.env`。
- 配置日志目录。
- 配置自动重启。

### 11.3 安全加固

- 后台只允许 HTTPS。
- 生产环境关闭调试信息。
- 设置强 `ADMIN_INIT` 关闭机制。
- 设置上传文件类型校验。
- 设置上传文件大小限制。
- 设置接口限流。
- 设置登录失败锁定。
- 数据库账号最小权限。
- 禁止前台访问后台内部接口。

### 11.4 验收标准

- `https://szht.online` 可访问展示端。
- `https://admin.szht.online` 可访问后台。
- 未登录无法进入后台。
- 前台不泄露未发布数据。
- 上传、审核、发布完整跑通。
- 服务器重启后服务自动恢复。

- 是否允许使用服务器测试 MySQL。
- 测试数据库名称。
- 测试数据库账号。
- 测试数据库密码。
- 后台初始化入口策略。
- 管理端 UI 是否接受实用型 CMS 风格。
- 第一里程碑是否锁定阶段 0 到阶段 3。

## 17. 暂定实施顺序

1. 阶段 0：开发准备与架构确认。
2. 阶段 1：管理后台基础底座。
3. 阶段 2：统一内容模型与审核流。
4. 阶段 3：核心内容闭环。
5. 阶段 4：全模块迁移。
6. 阶段 5：导入导出与批量管理。
7. 阶段 6：备份恢复与运维后台。
8. 阶段 7：正式部署与安全加固。
9. 阶段 8：增强优化。

## 18. 当前结论

本项目不建议继续以“给现有前端补几个接口”的方式推进。

正确落地方式是：

- 新建独立管理端。
- 后端切换 MySQL。
- 先做账号权限和审核流。
- 再迁移档案、留言、媒体等核心模块。
- 最后全量迁移其他前端静态模块。

这套路线能最大限度降低后期返工，并满足正式服务器、正式域名、政治敏感内容审核、多人协作管理的要求。
