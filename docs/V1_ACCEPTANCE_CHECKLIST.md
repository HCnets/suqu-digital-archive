# V1.0 上线验收清单

本清单用于正式部署前最后一轮验收。执行人可以是项目负责人、政府工作人员代表、讲解员代表和技术运维人员共同完成。

人工业务验收完成后，需要在后台 `运维管理 -> V1.0 上线验收登记` 中保存最终结论、负责人、正式域名验收结果、手机端验收结果、真实素材验收结果和遗留事项。

验收结论只允许三种：

- `通过`：所有必选项完成，未发现阻塞问题。
- `有条件通过`：只剩不影响数据安全和正式运行的轻微体验项，并已登记负责人。
- `不通过`：存在任一阻塞项，必须修复后重新验收。

## 2. 机器验收

在正式服务器或等价环境执行：

```bash
cd /www/wwwroot/szht/client
npm install
npm run build:server

cd /www/wwwroot/szht/admin
npm install
npm run build

cd /www/wwwroot/szht/server
npm install --omit=dev
npm run db:smoke:mysql:acceptance
npm run acceptance:v1:evidence
```

健康检查必须满足：

```text
store = mysql
configuredStore = mysql
database.runtimeClient = mysql
database.runtimeAligned = true
```

## 10. 阻塞项判定

出现以下任一情况，本轮验收为 `不通过`：

- 健康检查不是 MySQL 正式运行态。
- `npm run db:smoke:mysql:acceptance` 失败。
- `npm run acceptance:v1:evidence` 无法生成证据文件。
- 管理端无法登录或无法提交审核。
- 审核通过后公开接口读取不到已发布内容。
- 上传文件丢失、无法打开，或 `DATA_DIR` 在公开静态根目录内。
- 备份无法创建，或恢复后关键数据丢失。
- 普通运营路径要求填写 JSON、内部枚举、数据库编号等技术字段。
- 手机端无法完成查看待办、审核内容、管理媒体。
