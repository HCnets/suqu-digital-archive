# 后端上线前审计报告

审计时间：2026-07-16

目标：先判断当前后端是否适合快速上服务器，再拆出第一步可开发版本，便于在不降低质量的前提下尽快进入真实服务器试运行。

## 1. 当前结论

当前项目已经不是纯静态站点。现状是：

- 后端：`server/index.js`，Node.js + Express + SQLite。
- 管理端：`admin/`，独立 React/Vite 后台应用。
- 展示端：`client/`，仍由后端 API 驱动部分公开数据。
- 数据目录：由 `DATA_DIR` 控制，数据库、上传、备份均应放在网站根目录之外。
- 生产域名规划：展示端 `szht.online`，管理端 `admin.szht.online`，两个站点的 `/api/` 反向代理到后端。

判断：

- 可以作为“SQLite 试运行版”快速上服务器测试，但需要先补一轮上线硬化。
- 不建议直接作为长期正式生产版承载真实采集数据，因为 MySQL、升级系统、完整运维安全还没完成。
- 如果目标是“先让服务器跑起来、后台可用、能做真实流程演练”，优先做 V0.9。
- 如果目标是“直接进入长期生产数据库”，优先做 V1.0 MySQL，但上线速度会慢一些。

## 3. 未达标或不建议直接上生产的部分

### 3.1 数据库仍是 SQLite

当前 `server/index.js` 直接使用 `node:sqlite` 的 `DatabaseSync`。这对本地开发和小规模试运行很方便，但不是你服务器长期推广平台的最终形态。

SQLite 优点：

- 不需要安装数据库服务。
- 一个文件即可备份和迁移。
- 本地开发快，适合先跑通功能。
- 小流量、单服务器、少量后台用户可以试运行。

SQLite 缺点：

- 并发写入能力有限。
- 权限、审计、备份、远程管理能力弱于 MySQL。
- 多地区推广、多人采编、媒体量增大后风险更高。
- 不能很好承接宝塔/phpMyAdmin 的数据库运维习惯。

MySQL 优点：

- 更适合长期生产、多用户、多地区、多数据量。
- 宝塔和 phpMyAdmin 已经可运维。
- 权限、备份、恢复、迁移、监控更成熟。
- 适合以后做一键安装包和多地区推广。

MySQL 缺点：

- 需要数据库连接层和迁移脚本。
- 本地测试环境要准备 MySQL 或 Docker。
- 初次开发成本高于 SQLite 快速上线版。

审计判断：如果要“尽快上服务器”，可以先做 SQLite 上线硬化版；如果要“一上去就作为长期正式数据库”，应先做 MySQL 基础版。

### 3.2 一键安装和滚动升级未完成

未完成项：

- 应用版本表。
- 安装向导的服务器环境检测。
- 升级包 manifest。
- 升级包签名验证。
- 超管上传升级包。
- 升级前自动备份。
- 升级失败回滚。
- 升级日志。
- 模板市场和地区模板导入。

影响：目前可以部署，但还不是“给其他地区一个安装包就能可视化安装”的平台形态。

### 3.3 生产安全仍需加强

已具备基础安全，但缺少生产增强：

- 审计日志哈希链。
- 审计导出签名。
- 敏感操作二次确认。
- 请求 ID。
- 统一中文错误码映射。
- 文件日志。
- 后台错误日志查看器。
- 管理端 IP 白名单或可选访问限制。
- 备份、恢复、导入、清空回收站、永久删除等高危操作的二次确认。

影响：政治敏感项目建议上线前至少完成 V1.2 的核心项。

### 3.4 备份恢复仍是早期形态

当前备份覆盖 SQLite 数据库和上传目录快照，但还缺：

- 压缩打包。
- 备份 manifest。
- 校验 hash。
- 备份保留周期。
- 一键下载备份包。
- 异地备份接口。
- MySQL 逻辑备份。
- 大文件上传目录增量备份。

影响：试运行可接受，正式生产不够。

### 3.5 媒体库还缺生产配额

当前有上传大小限制和类型校验，但缺：

- 全站总容量限制。
- 单用户每日上传限制。
- 单类型文件大小配置。
- 未引用文件清理。
- 上传失败残留清理。
- 视频转码队列化。
- ffmpeg/ffprobe 环境自检。

影响：上线试运行前建议至少加服务器自检和基础配额，避免磁盘被误占满。

### 3.6 AI 真实厂商适配未完成

当前是通用 OpenAI 兼容和通用异步回调框架，还没有：

- DeepSeek 专用预设。
- Mimo 官方 TTS/声音模拟适配。
- Mimo 文件上传。
- Mimo 音频生成状态轮询。
- 产物下载到本地媒体库。
- 厂商签名算法。
- 授权记录和声音模型绑定的完整工作流。

影响：AI 中心可以做框架演练和手动导入，不能宣称已完成真实 DeepSeek + Mimo 全链路。

### 3.7 后台运营体验仍有 JSON 残留

近期已经把很多重点 JSON 入口做成可视化编辑器，但仍存在部分低频复杂配置依赖 JSON 增强入口，例如：

- AI 供应商能力合同。
- 部分设备和场景配置。
- 复杂模板导入。
- 未来地区模板、栏目模板、审核流模板。

影响：开发人员可用，普通运营人员仍有学习成本。

### 3.8 构建与仓库卫生风险

当前 `.gitignore` 已忽略 `node_modules/`、构建产物、数据目录和 `.env`，这是正确方向。但当前工作区仍显示 `server/node_modules` 有大量变更痕迹。

影响：

- 不应把本机 `node_modules` 当上线产物。
- 服务器应执行 `npm install --omit=dev`。
- 推送前应清理或确认依赖目录不会进入版本管理。

## 4. 快速上服务器前最低建议

如果你选择先快速上服务器，我建议至少先做以下内容：

1. 生产自检接口和后台自检页：Node 版本、DATA_DIR 权限、SQLite 可写、上传目录可写、备份目录可写、ffmpeg/ffprobe、sharp、CORS、Cookie 域名。
2. 生产 `.env` 校验：缺少关键配置时给中文错误，不静默启动。
3. 基础配额：总容量、单文件大小、单用户每日上传次数/容量。
4. 备份增强：备份包 manifest、hash、压缩包、保留周期。
5. 敏感操作二次确认：导入、恢复、清空回收站、永久删除、重置高权限账号、AI Key 修改。
6. 错误日志：请求 ID、文件日志、后台日志查看。
7. 部署包整理：明确不上传 `node_modules`，提供宝塔 Node 项目和 Docker Compose 两条流程。

这一步仍然可以保持 SQLite，不阻断快速上线测试。

## 5. 第一实施版本选项

请从下面选择第一步先做哪一个版本。

### A. V0.9 服务器快速试运行版

目标：最快上服务器，先让真实域名、后台、上传、审核、备份跑起来。

包含：

- 生产环境自检页。
- `.env` 必填项校验。
- 宝塔 Node 项目部署包说明。
- Docker Compose 部署包说明。
- 备份压缩包、manifest、hash、保留周期。
- 基础上传配额。
- 敏感操作二次确认。
- 错误日志和请求 ID。

优点：最快能上服务器测试。

缺点：数据库仍是 SQLite，只适合试运行和小规模早期使用。

### B. V1.0 MySQL 基础版

目标：直接补齐长期生产数据库底座。

包含：

- 数据库适配层。
- MySQL schema。
- SQLite 到 MySQL 迁移脚本。
- MySQL 连接配置。
- 本地 Docker MySQL 或本机 MySQL 测试流程。
- 导入导出和备份恢复适配 MySQL。

优点：更接近正式生产。

缺点：开发量更大，上服务器时间更慢。

### C. V1.1 一键安装与升级平台版

目标：开始做可复制推广平台。

包含：

- 系统版本表。
- 安装向导。
- 安装环境检测。
- 升级包格式。
- 升级包签名。
- 升级前自动备份。
- 升级失败回滚。
- 后台系统更新页。

优点：符合未来推广目标。

缺点：如果没有先做 V0.9/V1.0，容易在部署细节上返工。

### D. V1.2 安全运维增强版

目标：强化政治敏感项目的审计与安全。

包含：

- 审计日志哈希链。
- 审计导出签名。
- 敏感操作二次确认全覆盖。
- 文件日志。
- 后台错误日志查看器。
- 管理端访问限制配置。
- 高危操作确认记录。

优点：安全质量明显提升。

缺点：不能单独解决 MySQL 和安装升级。

### E. V1.3 DeepSeek + Mimo AI 厂商适配版

目标：补真实 AI 能力。

包含：

- DeepSeek 文本模型预设。
- Mimo 官方 TTS 配置。
- Mimo 音频生成任务。
- 文件上传、轮询、下载转存。
- TTS 产物进入媒体库。
- 授权记录绑定声音对象。
- AI 结果进入审核。

优点：项目亮点更强。

缺点：需要你提供真实厂商 API 文档、Key、模型和接口限制；不适合作为最快上服务器第一步。

## 6. 我的建议

如果目标是“最快上服务器并保留后续升级空间”，我建议第一步选：

**A. V0.9 服务器快速试运行版**

做完后，服务器可以先试运行。随后第二步接：

**B. V1.0 MySQL 基础版**

这样既能尽快看到真实域名和后台运行，也不会把长期生产数据库无限后置。

如果你坚持“真实数据一开始就进长期生产库”，那第一步应直接选：

**B. V1.0 MySQL 基础版**

但上线节奏会比 V0.9 慢。
