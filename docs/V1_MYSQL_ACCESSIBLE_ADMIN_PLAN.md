# V1.0 上线基础版计划：友好后台 + MySQL

更新时间：2026-07-16

本阶段目标不是继续扩展 AI、升级包或模板市场，而是先把系统变成适合真实上线的基础版本：

1. 后台让不同年龄段、不同技术水平的人都能友好操作。
2. 数据库从当前 SQLite 开发/试运行形态切换到 MySQL 生产形态。
3. 做完后优先支持部署到 `szht.online` / `admin.szht.online` 的服务器。

## 1. 阶段边界

### 本阶段必须做

- 后台整体交互降复杂度。
- 后台默认进入“简明模式”，高级字段折叠。
- 高频工作流做成向导式操作。
- 表单错误、保存状态、上传状态、审核状态全部中文化和明显化。
- 内容、媒体、审核、用户、权限、运维这些核心模块统一交互。
- MySQL 数据库连接层。
- MySQL 建表脚本。
- SQLite 到 MySQL 迁移脚本。
- MySQL 备份/恢复基础脚本。
- 生产 `.env` 示例更新。
- 本地或服务器 MySQL 全链路验收。

### 本阶段暂不做

- DeepSeek/Mimo 专用厂商适配。
- 一键安装包市场。
- 在线升级包签名和回滚。
- 模板市场。
- 公开前台大改版。
- 复杂 BI 数据大屏。

这些后续继续迭代，不挡第一版上线。

## 2. 后台友好化设计原则

后台定位为“政务/教育类 CMS 管理系统”，不是程序员工具。

### 2.1 默认简明模式

默认展示：

- 今天要处理什么。
- 我能点什么。
- 下一步是什么。
- 操作成功了吗。
- 失败后怎么改。

默认隐藏：

- JSON。
- 原始响应。
- 复杂配置。
- 危险操作。
- 长表单中的低频字段。

高级用户可展开“高级设置”。

### 2.2 全年龄段友好

要求：

- 字号不小于 15px，正文优先 16px。
- 按钮面积更大，主次清晰。
- 表单分组清楚，每组有简短标题。
- 必填项明确标记。
- 错误提示直接告诉用户怎么修。
- 保存/提交/审核/上传必须有明确反馈。
- 表格操作不能只靠小图标，关键按钮保留文字。
- 危险操作必须二次确认。

### 2.3 核心工作流向导化

优先优化这些流程：

- 新建档案点位。
- 新建口述历史。
- 上传媒体。
- 提交审核。
- 审核通过/驳回。
- 创建用户和分配权限。
- 导入导出与备份。

示例：新建档案点位分为：

1. 基本信息。
2. 地图位置。
3. 图文媒体。
4. 来源依据。
5. 审核与发布位置。

### 2.4 JSON 收口策略

本阶段不要求一次性消灭所有 JSON，但要求：

- 普通路径不需要看到 JSON。
- 低频复杂字段放进“高级设置”。
- 高级设置必须有说明和示例。
- 保存失败时定位到具体字段。
- AI 供应商能力配置等技术字段暂时保留高级入口。

## 3. MySQL 切换策略

当前后端大量使用 SQLite 同步 API，不能简单替换一行配置。需要分层迁移。

### 3.1 推荐架构

新增数据库适配层：

- `server/db/sqlite.js`：保留本地开发和迁移源。
- `server/db/mysql.js`：生产 MySQL 实现。
- `server/db/index.js`：根据 `DB_CLIENT=mysql|sqlite` 选择。
- `server/schema/mysql.sql`：MySQL 建表结构。
- `server/scripts/migrate-sqlite-to-mysql.js`：迁移脚本。
- `server/scripts/mysql-backup.js`：MySQL 逻辑备份。

### 3.2 迁移原则

- SQLite 继续作为本地开发和迁移源保留。
- 生产环境默认使用 MySQL。
- `.env.production.example` 改为 MySQL 配置。
- 迁移脚本必须支持先备份再导入。
- 迁移后校验核心表数量。
- 不把上传文件放进 MySQL，只迁移媒体记录和文件路径。

### 3.3 MySQL 表结构要求

必须覆盖当前核心表：

- `admin_users`
- `roles`
- `permissions`
- `role_permissions`
- `user_role_overrides`
- `user_regions`
- `sessions`
- `login_attempts`
- `regions`
- `content_modules`
- `review_workflows`
- `review_workflow_steps`
- `contents`
- `content_versions`
- `content_sources`
- `content_review_tasks`
- `media_assets`
- `messages`
- `tributes`
- `audit_logs`
- `risk_tag_templates`
- `ai_providers`
- `ai_tasks`
- `ai_call_logs`

### 3.4 MySQL 上线验收

必须通过：

- 首次创建超级管理员。
- 登录、退出、刷新会话。
- 创建用户、分配角色、分配地区。
- 上传图片、音频、视频、PDF。
- 创建档案点位并提交审核。
- 审核通过后公开接口可读取。
- 创建口述历史并上传授权文件。
- 导出、导入、备份。
- 操作日志可筛选。
- 重启服务后数据仍在。

## 4. 本阶段实施顺序

### 第一步：后台友好化骨架

- 统一页面标题、提示、空状态、错误状态。
- 增加简明模式/高级模式。
- 优化首页工作台：待办、快捷入口、最近操作、上线检查。
- 优化表单基础组件：必填、说明、错误、成功提示。

### 第二步：核心流程向导化

- 档案点位创建向导。
- 口述历史创建向导。
- 媒体上传向导。
- 审核详情优化。
- 用户和权限分配优化。

### 第三步：MySQL 数据层

- 增加 MySQL 依赖。
- 抽象数据库访问层。
- 写 MySQL schema。
- 改造后端启动流程。
- 增加 DB 健康检查。

### 第四步：数据迁移

- SQLite 导出当前数据。
- MySQL 建库建表。
- 数据导入 MySQL。
- 上传目录保持文件系统迁移。
- 校验核心表数量和关键记录。

### 第五步：上线验收

- 本地或服务器 MySQL 全链路测试。
- 更新部署文档。
- 更新生产 `.env`。
- 准备宝塔 Node 项目部署流程。

## 5. 已确认的用户决策

### 5.1 使用人群

主要使用者不是 IT 工程师，而是：

- 政府工作人员。
- 讲解员。
- 内容采集团队。
- 审核人员。
- 项目管理人员。

后台必须默认服务“业务人员”，不是服务“开发人员”。

### 5.2 后台模式

支持模式切换：

- 标准模式：默认模式，稳重清爽，信息密度适中。
- 宽松大字模式：字号、按钮、表格行高、输入框高度同步放大。
- 高效紧凑模式：给熟练人员使用，提高信息密度。
- 主题风格支持切换：清爽政务主题、红色文化主题。

模式和字号偏好需要记住到账号偏好里，下次登录继续生效。

### 5.3 菜单和角色视角

左侧菜单按任务分组，不再只是平铺模块：

- 工作台
- 内容与素材
- 审核发布
- 系统管理

不同角色看到不同首页和入口：

- 普通操作员只看到自己能操作的内容。
- 超级管理员可以决定无权限功能是隐藏，还是显示灰态并提示联系管理员。
- 讲解员需要专门的“讲解资料工作台”，可查看已发布内容、路线、讲解词、媒体资料，也能在手机端完整管理允许的内容。
- AI 中心默认归入系统管理，避免普通用户被复杂项干扰；超管可决定给谁看。

### 5.4 工作台

后台首页不强制改成“我的待办”唯一视图，但必须做成清晰的“今日工作台”：

- 待审核。
- 待补资料。
- 最近退回。
- 最近上传。
- 快捷新建。
- 我的权限范围。
- 系统状态。
- 数据库状态：MySQL / 正常 / 最近备份时间。
- 常用功能可手动排序，也可以按用户常用路径自动推荐。

### 5.5 新建中心

必须有“新建中心”，入口按用户意图命名：

- 新增一个红色点位。
- 录入一次采访。
- 上传一批图片视频。
- 创建一条讲解路线。
- 添加红歌资料。
- 添加影片资料。
- 创建学习题。
- 发布或精选群众留言。

每种内容入口需要示意卡片，说明“这是什么、适合什么资料、需要准备什么”。

### 5.6 向导式录入

所有高频内容创建都采用分步骤向导：

- 支持填写时自动保存。
- 自动保存频率可配置。
- 自动保存状态明显显示，例如“已自动保存于 14:32”。
- 网络断开时提示“当前未保存，请不要关闭”，恢复后自动继续保存。
- 每一步底部按钮固定且直白：上一步、保存并下一步、保存草稿、提交审核。
- 允许跳过非关键项，但未补齐必填项不允许提交审核或发布。
- 顶部显示“还差 N 项才能发布”，点击可跳转定位。
- 向导开始前展示需要准备的材料。
- 填到一半离开页面必须保留草稿。

### 5.7 全局搜索

需要顶部全局搜索，结果按类型分组：

- 内容
- 媒体
- 用户
- 审核
- 日志
- 帮助

搜索需要支持关键词、模糊搜索和拼音搜索，例如输入 `suqu` 能找到“苏区镇”。

### 5.8 帮助中心

需要帮助中心，并支持后台可编辑。

要求：

- 每个页面右上角有帮助入口。
- 帮助内容按页面组织。
- 支持全局搜索问题。
- 支持“当前页面操作步骤”。
- 预留视频/动图教程位置，第一版可先放文字步骤。
- 页面顶部不单独堆说明文字，说明统一放到帮助入口中，避免界面变乱。

## 6. 普通路径零 JSON 原则

V1.0 必须把“扩展数据”“媒体数据”“JSON”从普通操作路径中移除。

### 6.1 硬标准

- 普通用户不能被要求填写 JSON。
- 普通用户不能看到“扩展数据 JSON”“媒体列表 JSON”“输入 JSON”这类字段。
- 普通用户通过上传、选择、拖拽、卡片、预览、勾选、地图点选完成全部操作。
- JSON 只保留在超管高级诊断区，默认隐藏，并标注“仅技术人员使用”。
- 超管可决定哪些高级能力对哪些账号可见。

### 6.2 替代方式

原有 JSON/技术字段必须替换为：

- 素材选择器。
- 区块编辑器。
- 卡片式多条目编辑。
- 时间线编辑器。
- 题库编辑器。
- 来源依据编辑器。
- 地图点选器。
- 审核清单。
- 模板配置器。

### 6.3 必须覆盖的内容类型

第一批可视化编辑必须覆盖：

- 档案点位。
- 口述历史。
- 红歌。
- 影片。
- 党日路线。
- 学习题库。
- 今日苏区。
- 时间轴。
- 群众共创。
- 宣誓墙。
- 致敬仪式。

## 7. 受控区块编辑器

后台编辑体验参考 WordPress 的易用性，但不能让样式随意失控。

### 7.1 区块机制

内容编辑采用“受控区块编辑器”：

- 用户点击“添加区块”。
- 从允许的区块类型中选择。
- 区块以卡片形式编辑。
- 区块支持拖拽排序。
- 区块支持复制、删除、折叠、预览。
- 区块支持多步撤销/重做。
- 手机端支持长按拖动和上移/下移按钮两种排序方式。

### 7.2 受控样式

为避免页面风格割裂：

- 区块样式只允许选择预设。
- 用户不能自由改字体、颜色、边距。
- 模板限制可用区块和大顺序。
- 超管可决定每种内容类型能使用哪些区块。
- 超管可决定哪些区块必填、可选、可重复。

### 7.3 内容模板

每种内容类型都需要默认模板：

- 档案点位模板。
- 口述历史模板。
- 红歌模板。
- 影片模板。
- 党日路线模板。
- 学习题模板。
- 今日苏区模板。
- 宣誓墙模板。
- 致敬仪式模板。

超管可自定义模板：

- 默认区块。
- 允许区块。
- 必填字段。
- 发布前检查项。
- 审核清单。
- 默认发布位置。

### 7.4 预览

提交审核前必须支持预览：

- 编辑预览：后台审阅效果。
- 前台预览：尽量接近公开端真实展示。
- 设备预览：电脑、手机、大屏。

## 8. 媒体与素材选择器

媒体库需要从表格工具升级为“素材工作台”。

### 8.1 默认体验

- 默认使用网盘/相册式视图。
- 高级模式可切换表格资料库视图。
- 支持批量上传。
- 批量上传后统一填写分类、水印、说明。
- 上传后进入逐个确认页面。
- 上传完成后提示下一步：继续上传、插入内容、新建档案点位、作为封面图等。

### 8.2 素材选择器

内容编辑中不再复制路径。

必须支持：

- “上传新素材”和“从已有素材选择”在同一个弹窗里。
- 按用途自动过滤素材类型。
- 选择封面图时只显示图片。
- 选择授权文件时只显示 PDF/图片。
- 选择讲解音频时只显示音频。
- 选择视频资料时只显示视频。
- 支持拖拽排序。
- 支持设为封面。
- 支持裁剪封面图。
- 支持视频手动选择某一帧作为封面。
- 显示素材已被哪些内容使用。

### 8.3 删除保护

- 媒体被内容使用时禁止直接删除。
- 必须先解除引用，或由超管在高危确认后处理。
- 删除先进入回收站。
- 删除或批量修改后提供 5 分钟撤销。
- 永久删除只允许超管，并要求输入确认文字。

### 8.4 智能分类

媒体库需要支持智能视图：

- 最近使用。
- 未使用素材。
- 缺少说明。
- 缺少水印。
- 上传失败。

## 9. 地图点选与高德地图

档案点位是项目核心，地图不能留空到后续阶段。

### 9.1 地图服务选择

V1.0 优先接入高德地图 JS API。

原因：

- 国内访问稳定性较好。
- Web 地图、地理编码、行政区划能力较完整。
- 适合当前红色点位、地区范围、地址辅助定位场景。

### 9.2 Key 与安全

原则：

- 前端地图展示可以使用浏览器端 Key。
- 地址解析、逆地址解析、行政区检索等敏感调用优先走后端代理。
- 后端保存服务端 Key，不在普通后台明文回显。
- 超管在系统管理中配置地图服务。

### 9.3 点位录入

后台地图点选器必须支持：

- 手动输入地址。
- 点击“查找位置”。
- 显示候选点。
- 用户确认候选点后写入位置。
- 在地图上直接点选。
- 地图拖动微调。
- 自动显示经纬度，但不要求用户理解经纬度。
- 支持手动输入经纬度作为高级入口。

### 9.4 地区边界限制

需要支持行政区边界范围限制：

- 超管可按地区配置边界。
- 内容录入时只能在授权地区范围内点选。
- 点到边界外时给出明确提示。
- 支持苏区镇、紫金县，以及未来省/市/县/镇/村多级地区。
- 支持后续一个后台多地区，也支持单地区独立后台。

## 10. 审核体验

审核页要像“审稿台”，重点防误发、错发、无依据发布。

### 10.1 审核任务分组

审核任务需要按角色和风险自动分组：

- 我负责初审。
- 我负责终审。
- 我退回过的。
- 高风险优先。

### 10.2 审核详情

审核详情采用一屏式审阅：

- 左侧：内容正文、区块、媒体预览。
- 右侧：审核清单、风险标签、来源依据、审核历史、操作按钮。
- 审核按钮滚动时固定。
- 支持大字审阅模式，隐藏侧栏，集中看正文、媒体、来源和审核按钮。

### 10.3 审核清单

审核清单按内容类型不同而不同：

- 档案点位：地图位置、来源依据、图片视频、发布位置、敏感表述。
- 口述历史：授权文件、公开版本、敏感片段、音视频、AI 摘要人工核对。
- 红歌：版权或来源、歌词、音频、适用场景。
- 影片：版权或来源、封面、简介、推荐理由。
- 路线：点位顺序、讲解词、安全提示、地图位置。

高风险内容必须勾完审核清单才能通过。

### 10.4 驳回与批注

- 驳回必须选择问题类型。
- 可选择退回到指定步骤。
- 可写原因，也可使用模板。
- 审核员可在具体区块上标注问题。
- 右侧显示批注栏。
- 点击批注可定位到对应区块。

## 11. 来源、时间线、题库等专用编辑器

### 11.1 来源依据编辑器

来源依据必须支持：

- 上传证明材料：图片、PDF、采访记录。
- 填写网页链接。

## 16. V1.0 验收主流程

V1.0 必须至少通过以下全链路：

1. 启动 Docker MySQL。
2. 迁移当前 SQLite 数据到 MySQL。
3. 首次创建或保留超级管理员。
4. 登录后台。
5. 切换标准/大字/高效模式。
6. 上传 5 个媒体素材，包括图片、音频、视频、PDF。
7. 使用素材选择器插入媒体，不复制路径。
8. 新建 1 条档案点位。
9. 使用高德地图查找地址、点选位置，并通过地区边界校验。
10. 使用区块编辑器编辑详情。
11. 添加来源依据、时间线、相关人物/事件。
12. 自动保存草稿。
13. 提交审核。
14. 审核员使用审核清单、批注、风险信息完成审核。
15. 审核通过并发布。
16. 前台公开接口可读取已发布内容。
17. 新建 1 条口述历史，上传授权文件。
18. 新建 1 条红歌资料。
19. 新建 1 条讲解路线。
20. 手机端完成查看待办、审核内容、管理媒体。

验收标准：新用户不看开发文档，也能在界面引导下完成上传、新建、提交审核、审核通过、发布查看。
