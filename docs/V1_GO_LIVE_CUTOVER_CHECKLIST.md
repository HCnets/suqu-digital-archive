用途：正式部署到 `szht.online` / `admin.szht.online` 前后使用。任何阻塞项未通过时，不进入正式开放。

| --- | --- | --- | --- |

## 3. 机器验收

```bash
cd /www/wwwroot/szht/admin
npm run build
```

```bash
cd /www/wwwroot/szht/server
npm run db:smoke:mysql:acceptance
npm run acceptance:v1:evidence
```

```bash
curl http://127.0.0.1:3001/api/health
```

健康检查必须满足：
- `store=mysql`
- `configuredStore=mysql`
- `database.runtimeClient=mysql`
- `database.runtimeAligned=true`

## 5. 放行条件

全部满足才允许正式开放：
- 机器验收通过
- 健康检查四个 MySQL 字段全部符合
- 业务验收没有阻塞项
- 最新验收证据已生成并归档
- 后台 `运维管理 -> V1.0 上线验收登记` 已保存最终结论

## 6. 回退条件

出现任一情况，立即暂停开放并回退：
- `/api/health` 不是 MySQL 正式运行态
- 管理端无法登录
- 上传文件丢失或无法打开
- 审核通过后公开接口读取不到内容
- MySQL 验收失败
- 备份恢复失败

## 7. 回退步骤

1. 暂停 Nginx 对外流量或临时切回维护页。
2. 保留当前故障现场日志。
3. 使用最近一次可用备份恢复。
4. 重启 Node 服务。
5. 重新执行健康检查和 MySQL 验收。
6. 在验收登记中记录故障原因、处理人和后续事项。
